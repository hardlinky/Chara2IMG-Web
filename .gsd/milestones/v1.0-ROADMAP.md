# Milestone Archive: v1.0 MVP

**Status:** SHIPPED
**Archived:** 2026-05-24
**Phase Range:** 1-5

## Milestone Description

Chara2Img Web v1.0 delivers invited-user end-to-end parity for Runpod-based ComfyUI workflows: secure access boundary, full workflow template import/reuse, dynamic typed input editing and apply-back, recent job lifecycle management, and output gallery/lightbox review.

## Phase Details (Archived from ROADMAP.md)

### Phase 1: Access and Proxy Boundary

- Goal: Invited users can securely access the app and use BYOK through a thin web proxy.
- Requirements: AUTH-01, AUTH-02, AUTH-03, AUTH-04
- Plans (5/5 complete):
  - 01-01 scaffold TypeScript/Hono baseline
  - 01-02 invited session middleware + access routes
  - 01-03 invite-gated UX + BYOK settings
  - 01-04 allowlisted Runpod proxy core
  - 01-05 typed proxy smoke + boundary tests

### Phase 2: Workflow Import and Template Reuse

- Goal: Users can import, validate, and reuse full-fidelity ComfyUI workflow templates.
- Requirements: WFLO-01, WFLO-02, WFLO-03, WFLO-04
- Plans (2/2 complete):
  - 02-01 import validation + normalization entry points
  - 02-02 persistent template reuse flow

### Phase 3: Dynamic Input Editing

- Goal: Users edit workflow-derived controls and apply values back into a run-ready payload.
- Requirements: INPT-01 to INPT-08
- Plans (2/2 complete):
  - 03-01 typed control derivation + editor state orchestration
  - 03-02 validation + canonical apply-back payload builder

### Phase 4: Job Lifecycle and Run Management

- Goal: Users submit, monitor, control, and revisit jobs with context reuse.
- Requirements: JOBS-01 to JOBS-08
- Plans (3/3 complete):
  - 04-01 submission contracts + persisted lifecycle metadata
  - 04-02 polling, timeout, and cancellation orchestration
  - 04-03 rerun/load-input/remove and compact recent-jobs UI

### Phase 5: Outputs and Gallery Review

- Goal: Users browse completed outputs with preserved provenance.
- Requirements: OUTP-01 to OUTP-04
- Plans (2/2 complete):
  - 05-01 deterministic image extraction + output projection clusters
  - 05-02 outputs tab gallery + dedicated job view + lightbox

## Milestone Summary

### Key Decisions

- Keep BYOK with browser-local remember behavior and avoid server-side long-term key storage.
- Preserve full canonical workflow JSON and rebuild run payload from template + draft each run.
- Use projection-first output contracts so outputs UI never parses raw Runpod payloads.
- Keep app navigation tab-driven and split concerns into Setup/Input/Jobs/Output post-Phase 5.

### Issues Resolved During Milestone

- Hardened proxy status response parsing and corrected status forwarding path handling.
- Expanded dynamic input parsing compatibility (`_meta.title`, optional `[Input]`, broader class-type mappings).
- Added endpoint ID env default with user override persistence to remove repetitive setup.
- Added lightbox wheel zoom and lora strength step tuning for better UX precision.
